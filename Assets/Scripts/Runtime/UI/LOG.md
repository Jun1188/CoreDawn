## 2026-08-03 — 이관 1단계: 디자인 시스템 + 코어 패널 (SCR-01)

### 왜 UITK인가

기존 UI는 전부 uGUI 런타임 코드 조립(BuildMenuPopup 등) — 씬 저작이 0이라 팀 병합에는
안전했지만, 스타일이 코드에 흩어져 있어 "간격 8px"을 바꾸려면 여러 파일을 뒤져야 했다.
UITK는 **구조(UXML)·스타일(USS)·동작(C#)이 분리**되고 스타일이 파일 하나에 모인다.

### USS 3층 구조

| 파일 | 역할 |
|---|---|
| `tokens.uss` | 색·간격·글꼴 크기 등 원시값 변수만. **여기 말고는 리터럴 색을 쓰지 않는다** |
| `components.uss` | 버튼·칩·게이지 등 재사용 조각 |
| `screens.uss` | 화면별 레이아웃 |

### USS 실측 제약 (추측 금지)

`StylePropertyUtil.s_NameToId`를 리플렉션으로 열어 **실제 지원 프로퍼티 99개**를 확인했다.
문서에 없어서 헤매기 쉬운 것들:

- **없음**: `gap` · `box-shadow` · `line-height` · `grid-*` · `z-index` · `outline` ·
  `background`/`border` 축약형 · `:last-child` · `:focus-within` · `align-items: baseline`
- **이름이 다름**: `font-weight` → `-unity-font-style`, `text-align` → `-unity-text-align`
- **`border-radius`가 x/y 반지름을 독립적으로 클램프** — 납작한 요소에 999px(알약)을 주면
  가로/세로가 따로 잘려 **타원**이 된다. 진행 바는 `height/2`를 직접 써야 함 (tokens.uss에 주석 박아둠)

### 구성 요소

- **`UITKPopup`** — 기존 `UIPopup` 파이프라인(열림 중 사격·건설 차단, ESC 닫기)의 UITK판.
  uGUI 팝업과 같은 표면이라 호출부는 어느 쪽인지 몰라도 됨
- **`CorePanelView`** — 코어 상태 화면. `TryOpen`이 **이미 열려 있으면 `Retarget()`으로 재바인딩** —
  `SetActive(true)`는 no-op이라 `OnEnable`이 안 불려서, 두 번째 코어를 열면 첫 번째가 보이던 버그
- **`RadarScope`** — `Painter2D` 벡터 드로잉. 데이터에 따라 매 프레임 달라지므로 SVG는 부적합
  (SVG는 임포트 시점에 구워짐. 6.3의 네이티브 SVG 지원은 확인했으나 정적 아이콘용)
- **`UIItemPalette`** — 아이템 계통색을 한 곳에서 결정 (`ItemLine` 소비자)
- **`CoreInfoDummyData`** — 아직 없는 시스템(티어·레이더 신호 등)의 자리를 더미로 채움.
  실제 시스템이 붙을 때 이 파일만 지우면 됨

## 2026-08-04 — 레이더 완성 + 건설 메뉴를 클릭 즉시 배치로

### 레이더 (`RadarScope`)

- **점선 원의 점 크기가 반지름마다 달라지던 것** — 대시를 각도로 지정했기 때문.
  **픽셀 호 길이**로 지정하고 반지름별로 각도 환산하도록 변경
- **NO SIGNAL이 코어 점과 겹침** — 레퍼런스의 비율(-0.13R)은 폰트 크기가 고정인데 R만 줄면
  깨진다. 코어 링 반지름 + 텍스트 높이 절반을 바닥값으로 하는 여유를 둠
- **진입점에서 뻗어나가는 지시선이 없고 점 위치도 어긋남** — 코어 쪽 점선 화살표만 그리고
  라벨로 가는 꺾인 선을 빠뜨렸음. 더미 거리도 0.95였으나 레퍼런스는 바깥 링(1.0).
  `EntryLeader()`가 꺾임점·꼬리를 한 번 계산해 **그리기와 라벨 배치가 같은 값**을 쓰게 함
- **레이더 꺼짐 상태에서 INCOMING·DESTROYED NESTS는 `???`** + "항법 계통 오프라인" 표기
- 아래 여백이 남아 레이더를 확대
- 가동 중 상태를 눈으로 확인할 수 있도록 더미 데이터 토글 제공

### 건설 메뉴

- **"배치 시작" 버튼 제거 — 행 클릭이 곧 배치 시작**. 한 번 더 누르게 할 이유가 없음
- **떠다니는 툴팁 → 하단 고정 상세 영역** (없어진 버튼 자리를 넓혀 사용).
  커서를 따라다니는 툴팁은 목록을 훑을 때 시선이 튄다

## 2026-08-04 — 배치·철거 모드 HUD (SCR-05 · SCR-06)

건설 메뉴에서 고르면 창이 닫히고 하단 카드 하나만 남는다 — 배치는 월드를 보면서 하는 일이라
화면을 덮으면 안 된다.

- **팝업이 아니다.** `UITKPopup`은 입력 맵을 Push하고 커서를 푸는데 HUD는 둘 다 하면 안 된다
  (배치 중에도 좌클릭이 `BuildController`로 가야 한다). `UIDocument`만 들고 표시/숨김만 맡는다
- **`.screen-root`를 쓰지 않는다** — 거기엔 모달용 스크림(반투명 검정)이 들어 있어 HUD가
  화면 전체를 어둡게 덮는다. 실제로 그렇게 만들었다가 고쳤다. 폰트만 `.hud-root`에 따로 준다
- 문서는 `BuildModeHUD`/`DemolishModeHUD` 두 파일로 적혀 있지만 **한 문서의 두 상태**로 만들었다.
  골격이 같고, 오갈 때 문서가 통째로 바뀌면 카드가 한 프레임 깜빡인다
- **홀드 진행 링**(`HoldRing`)은 `Painter2D` — USS로는 호(arc)를 못 그린다(레이더와 같은 이유).
  남은 시간 라벨은 **링의 자식**이어야 한다. 형제로 두면 `.ui-holdring`의 가운데 정렬이 닿지 않아
  절대 배치 기본값인 좌상단에 붙는다
- 갱신은 매 프레임 읽되 **실제로 바뀌었을 때만** 다시 만든다(건물·모드·보유량 스탬프 비교).
  조준·인벤토리·홀드 진행처럼 매 프레임 변하는 값이라 이벤트로 바꿔도 결국 매 프레임 발화한다
- **빠뜨린 것**: 설명문의 "건설 퀵바"(최근 건물을 숫자키로 전환)는 목업에 안 그려져 있어 만들지 않았다.
  DAY/NIGHT 스탯도 뺐다 — 기존 uGUI Day HUD와 이중으로 그려진다 (SCR-02 이관 때 통합)

### 건설 비용이 진짜 값이 됐다

- `BuildCostDummyData` 삭제, `BuildingDataSO.buildCost`를 읽는다. 그 파일이 자기 문서에 적어둔
  삭제 조건("비용 배열이 생기면 이 파일을 지우고 호출부를 바꿔라")이 충족됐다
- **"필요/보유" 표기**(10/31)에 모자란 칩만 통째로 붉힌다. 숫자가 이미 말하므로 문장으로 반복하지 않는다.
  건설 메뉴와 배치 HUD가 같은 문법 — 메뉴에서 본 것과 배치 중 보는 것이 어긋나지 않게
- **상세 영역에서 칩이 잘리던 것**: 라벨과 같은 줄에 두니 재료 4종(약 500px)이 내부 폭 588px를
  넘겨 칩 뭉치가 통째로 다음 줄로 밀렸다. 칩을 자기 줄로 분리하고 높이를 168px로

## 2026-08-04 — 코어 수리 확인창 (SCR-01b)

미뤄뒀던 항목. 선행 조건이던 게임플레이 변경을 여기서 함께 했다.

- **요구 충족과 실제 진행을 갈랐다** — `CoreBehavior.Tick`이 즉시 소비·진행하던 것을
  `IsReadyToRepair`(신호) / `TryStartRepair()`(실행)로 분리. 상세: Factory/LOG.md 2026-08-04
- 납품 버튼이 두 얼굴을 갖는다. 모자라면 "납품", 다 모이면 "수리 시작"으로 바뀌고
  부품 선택 UI가 사라진다 — 더 넣을 것이 없으니 남겨둘 이유가 없다
- 창 내용은 전부 단계 데이터에서 나온다: GATE 번호 · 이름 · 설명 · 해금 목록
- **경고 블록은 `isFinal`에만.** 전부에 붙이면 정작 위험한 마지막에서 눈에 띄지 않는다.
  그 단계만 버튼이 `--danger "예열 시작"`이 되어 무슨 일이 일어날지 버튼이 말한다
- **내구도 줄은 `unlocks`에 손으로 적지 않고 `maxHpBonus`에서 생성**한다. 같은 수치를 데이터와
  문구 두 곳에 적으면 반드시 어긋나고, 어긋난 쪽이 UI면 플레이어가 속는다.
  목업의 "자동" 배지는 문서용 표시로 읽고 넣지 않았다 — 플레이어에게는 다른 해금과 구분할 이유가 없다
- **뺀 것**: 경고 블록의 "예열 시간 05:00" — 최종 방어전 타이머 시스템이 아직 없다
