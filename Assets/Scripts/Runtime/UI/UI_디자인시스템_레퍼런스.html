01

색상 토큰

USS: --변수명 그대로

색은 세 갈래로만 쓴다. 배경 계층은 깊이를, 계통색은 자원·부품의 소속을, 상태색은 지금 무슨 일이 일어났는지를 말한다. 계통색은 테크트리 문서와 같은 값이라 기획서와 게임 화면이 자동으로 일치한다.

배경 · 선 · 글자

--bg-void#0B1220화면 최하단. 3D 위에 덮이는 반투명 배경도 이 색 기준
--bg-panel#111B2E패널 본체. 창·팝업의 기본 바닥
--bg-inset#0E1727패널 안에 파인 영역 — 슬롯, 입력칸, 진행바 트랙
--bg-raised#16243C호버·선택된 행. 버튼 기본 바닥
--line#223350구분선, 비활성 테두리
--line-strong#2E4266패널 외곽선, 슬롯 테두리
--text#D9E4F5본문·수치. 순백은 쓰지 않는다
--text-dim#8FA3C0보조 설명, 비강조 항목
--text-faint#5C6E8C라벨, 단위, 키 힌트

계통색 — 소속을 말한다

--iron#E8A54B구조 계통. 철광석·철판·선체 패널·물리 탄약
--copper#4FD8E0전자 계통. 구리·회로·제어 유닛. UI 기본 강조색 겸용
--crystal#B48CFF동력 계통. 크리스탈·에너지 셀·동력 모듈
--beast#FF5D73괴수 소재·둥지·적대 요소

상태색 — 일어난 일을 말한다

--ok#5DD39E완료, 충족, 가동 중
--warn#E8A54B부족, 대기, 곧 시작 (= --iron)
--danger#FF5D73피해, 파괴, 되돌릴 수 없는 조작 (= --beast)

상태색이 계통색과 값을 공유한다. 의도된 것이다 — 괴수와 위험은 둘 다 "적대", 철과 경고는 둘 다 "주의해서 다룰 것"을 뜻한다. 다만 USS 변수는 반드시 분리해서 선언할 것. 나중에 밸런스나 아트 방향이 바뀌어 둘을 갈라야 할 때, 변수만 다른 값으로 바꾸면 끝난다.

레이더는 목록이 아니라 스코프다 — 코어가 중심, 동심원이 곧 맵의 Ring 1~3이라 미니맵 역할을 겸한다. 진입 방위와 규모는 표에 적지 않고 스코프 위에 지시선으로 붙인다: 붉은 점이 진입 지점, 점선 화살표가 진행 방향, 바깥 라벨이 방위각과 규모다. 지시선은 진입 지점이 있는 쪽으로 뻗는다 — 오른쪽 지점은 오른쪽 라벨, 왼쪽 지점은 왼쪽 라벨(우측 정렬). 스코프 좌우에 라벨용 여백을 항상 확보해 두면 방위가 어디든 같은 규칙으로 그려진다. 개별 적도, 플레이어 자신도 표시하지 않는다 — 코어에 설치된 장비를 들여다보는 화면이므로 중심은 언제나 코어다. 밤새 움직이는 점을 쫓는 화면이 아니라 어디를 막을지 정하는 화면이기도 하고. 기호는 형태로 구분한다 — 삼각=둥지, 원=진입 지점, 마름모=광맥. 형태가 다르면 범례 없이도 몇 번 보면 외워지므로 스코프 아래 설명줄은 두지 않는다. 광맥은 계통색 다이아몬드로 찍는다 — 낮에 어느 쪽으로 채굴을 나갈지 정하는 화면이기도 하므로, "북동쪽 Ring 2에 크리스탈"을 둥지 위치와 함께 보고 판단하게 된다. 색으로 성격을 가른다: 붉은 삼각 = 둥지(늘 거기 있는 스폰원, 낮에 칠 대상), 주황 점 = 이번 웨이브 진입 지점(오늘 밤 막을 곳). 하나는 장기 목표, 하나는 당장의 위협이라 절대 같은 색을 쓰지 않는다.

패널을 화면 하단에 붙여 핫바가 HUD의 핫바와 같은 자리에 오게 한다 — I를 눌러 열고 닫아도 핫바는 움직이지 않는다. 손이 기억하는 위치가 유지되고, 격자에서 핫바로 아이템을 끌어 내리는 동작이 화면상의 실제 방향과 일치한다. 위에서 아래로 제작 → 소지품 → 핫바 순. 격자는 빈 칸까지 전부 그려 칸 수가 곧 소지 한도임을 보여주고, 제작 영역만 가로 2단인데 목록과 상세는 함께 봐야 고를 수 있기 때문이다. 수동 제작은 인벤토리 안에 들어간다 — 티어 0~1에서만 쓰는 기능에 별도 화면을 주면 자동화 이후 죽은 UI가 남는다. 목록에는 해금된 레시피만 올린다 — 해금되면 전부 수동 제작이 가능하므로 "잠김" 줄을 보여줄 이유가 없다. 대신 티어가 오르면 목록이 계속 길어지므로 검색과 스크롤을 처음부터 넣는다. 제작은 수량을 미리 고르지 않고 버튼을 누르고 있는 동안 계속 만든다 — 버튼 안이 차오르면 한 개 완성, 떼면 그 자리에서 멈춘다. 몇 개가 필요할지 미리 세지 않아도 되고, 재료가 떨어지면 자동으로 멈춘다. 시간은 목록의 회당 시간(레시피 비교용), 상세의 시간 배지, 진행 중 현재 항목 잔여 세 군데에 나온다. 재료는 계통색 띠로 표시해 어느 라인에서 나온 것인지 바로 읽힌다.

UITK 이식 규약

Claude Code 작업 기준

파일 배치

Assets/Scripts/Runtime/UI/ ├── Styles/ │ ├── tokens.uss /* :root 변수만 */ │ ├── components.uss /* .ui-* 전부 */ │ └── screens.uss /* 화면별 예외 */ ├── Screens/ │ ├── CorePanel.uxml │ ├── GameplayHUD.uxml │ ├── BuildMenuPanel.uxml │ └── InventoryPanel.uxml ├── Views/ │ ├── CorePanelView.cs /* 바인딩만 */ │ ├── GameplayHUDView.cs │ └── ... └── UITKPopup.cs /* UIPopup 상속 */

기존 UI 스크립트가 Assets/Scripts/Runtime/ 아래 있으므로 UI도 같은 트리에 둔다. tokens.uss는 이 문서의 :root를 그대로 옮긴 것이다. USS도 var(--이름) 문법을 지원하므로 변환이 거의 필요 없다.

클래스 이름 규칙

/* 블록 */ .ui-panel { ... } /* 요소 — 두 밑줄 */ .ui-panel__title { ... } /* 변형 — 두 하이픈 */ .ui-btn--primary { ... } .ui-chip--iron { ... } /* UXML에서는 조합해서 붙인다 */ <Button class="ui-btn ui-btn--primary" />

변형을 새 클래스로 만들지 않는다. .ui-btn-primary가 아니라 .ui-btn + .ui-btn--primary. 기본 스타일이 한 곳에만 있어야 한다.

기존 입력 시스템과 연결

저장소의 UIPopup — OnEnable에서 입력 맵 Push + 커서 해제, OnDisable에서 Pop + 잠금 — 은 이미 잘 동작하므로 그대로 쓴다. UITK 패널용 베이스를 하나 얹기만 하면 된다.

public class UITKPopup : UIPopup { [SerializeField] protected UIDocument document; protected VisualElement Root => document.rootVisualElement; protected override void OnEnable() { base.OnEnable(); // 입력 맵 Push · 리시버 등록 (기존 계약 유지) Root.style.display = DisplayStyle.Flex; Bind(); // 이벤트 구독 + 초기 1회 갱신 } protected override void OnDisable() { Unbind(); Root.style.display = DisplayStyle.None; base.OnDisable(); // 입력 맵 Pop · 커서 재잠금 } protected abstract void Bind(); protected abstract void Unbind(); }

1번이 끝나면 components.uss가 확정된다. 이후는 같은 클래스의 재조합이라 속도가 붙는다.

주의할 것

  • 월드 스페이스는 예외 — 몬스터 체력바, 설비 위 아이콘은 UGUI로 남긴다. UITK 월드 스페이스 지원은 6.3에서 먼저 확인할 것.
  • Update 폴링 금지 — 현재 SystemUIManager가 매 프레임 HUD를 갱신한다. 이관 시 이벤트 구독으로 바꾼다. 시간 표시처럼 진짜 매 프레임이 필요한 것만 예외.
  • 커서 처리 일원화 — BuildMenuPopup·SplitterFilterPopup이 커서를 직접 만지고 있다. 이관하며 UITKPopup 계약으로 흡수.
  • 인라인 스타일 금지 — 이 문서의 목업에는 레이아웃용 인라인 style이 있지만, 실제 UXML에서는 전부 클래스로 뺀다. 예외는 진행바 width처럼 런타임 값뿐.

이 문서를 열어둔 채로 작업할 것. 브라우저 개발자도구로 요소를 찍으면 실제 적용된 값이 그대로 보이고, 그게 곧 USS에 들어갈 값이다. 컴포넌트를 새로 추가하면 이 문서에도 부품 코드를 하나 늘린다.
