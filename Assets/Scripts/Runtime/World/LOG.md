# World — 맵 데이터와 길찾기 지형

월드가 "어디서 만드는가"를 정의한다. `GameData.json`이 "무엇을 만들 수 있는가"라면
`MapData.json`은 그 무대다 — 타일·광맥·둥지가 맵마다 다르므로 파일을 나눈다.

---

## 2026-08-15 — 맵 데이터 파이프라인 + 비용 기반 길찾기

### 데이터 흐름

```
맵 에디터(HTML) → MapData.json → MapImporter → MapDataSO → World(씬) → 부트스트랩이 배포
```

- **`MapDataSO`** — 타일 격자(바이트, 행 우선)·코어 자리·광맥·둥지. 문자열로 두지 않는 이유는
  런타임에 매 칸을 조회하기 때문이다(121×121 = 14,641B). **맵 밖은 절벽으로 취급**해
  경계 검사가 따로 필요 없다.
- **`MapImporter`** — `Tools > Factory > Import Map Data (JSON)`. id로 제자리 갱신(참조 보존),
  파싱 실패는 에러(조용한 기본값 폴백 없음), 광맥의 `item`은 GameData에서 해석,
  `triggerRange > warningRange`면 경고(경고 없이 습격당하는 배치).
- **`World`** — 월드 씬의 유일한 배선. 맵 SO와 cellSize를 들고, **오브젝트 위치가 맵 (0,0)**.
  기즈모로 맵 경계·코어 자리를 그린다.

### 타일 규칙 — 한 곳에 모은다 (`TileRules`)

타일 종류는 맵이 갖고, "그래서 어떻게 되는가"는 규칙이 갖는다. 판정마다 흩어져 있으면
강 하나 조정에 세 곳(길찾기·배치·이동)을 고쳐야 하고 서로 어긋난다.

| 타일 | 진입 비용 | 이동 속도 | 건설 |
|---|---|---|---|
| 지면 | 10 (기준) | 1.0 | O |
| 강 | 30 | **0.5** | X |
| 절벽·맵 밖 | ∞ | — | X |

강이 통행 O·건설 X인 것이 설계의 핵심이다 — "지나갈 수는 있지만 방어선을 세울 수 없는 길".

### 비용이 정본, 통행 가부는 파생

처음엔 `IsWalkable`(bool)과 `EnterCost`를 별개 로직으로 뒀다가 통합했다. 질문이 둘일 뿐
판정은 하나다:

```csharp
EnterCost(cell, passBuildings)   // 정본
  true  진격(플로우필드) — "건물을 뚫고 갈 때 얼마?" → 지형 + min(HP×0.5, 200)
  false 보행(A*·군중·스폰) — "건물을 놔두고 갈 때 얼마?" → Blocked

IsWalkable(cell, ignoreBuildings) => EnterCost(...) < Blocked   // 얇은 별칭
```

- **건물을 유한 비용으로 두는 이유**: 목표가 아닌 건물(벨트)로 길을 막으면 몬스터가 갈 곳을
  잃고 굳어버린다(`CollectGoals`가 벨트를 목표에서 제외한다). 비싸지만 유한하면 플로우필드가
  "여길 뚫어라"는 방향을 주고, 도달한 몬스터가 사거리 판정으로 부순다.
- **HP 비례 + 상한**: 약한 곳(벨트 30)부터 뚫리고 튼튼한 곳(울타리 125)은 우회한다.
  상한이 없으면 코어(HP 5000)가 사실상 통행 불가가 되어 봉쇄가 성립한다.
  **상한 200 = 20칸 우회**가 기준이다 — 그보다 멀리 돌아가느니 뚫는 게 낫다는 뜻이고,
  121칸 맵에서 "벽 하나 때문에 맵을 가로지르지는 않는다"는 선이 된다.
- **A*는 건물을 막아야** `ChaseState`의 대비(ignoreBuildings 경로 vs 실제 경로)로 범인 건물을
  찾아 부수는 흐름이 성립한다. 그래서 같은 함수를 파라미터만 달리해 쓴다.

### 대각선

양옆 직교 칸이 **물리적으로** 열려 있어야 한다(`IsWalkable` 기준) — 절벽이든 건물이든
모서리는 못 스친다. 직교로는 건물을 뚫고 갈 수 있지만(비용), 대각으로 두 건물 사이 틈을
공짜로 빠져나가는 것은 물리와 맞지 않는다.

### 무엇부터 노리는가 — 시드 비용

플로우필드는 목표 전부를 큐에 넣고 한 번 퍼뜨리는 **다중 시작점 다익스트라**다(필드는 한 벌).
시드는 그 경쟁에서 목표별 핸디캡이다 — 10이 한 칸이므로 시드 30은 "3칸만큼 멀게 친다".

`BuildingDataSO.threatSeedCost`로 건물이 자기 위협도를 선언한다:
코어 0(최종 목표) · **공격 타워 10**(가는 길에 먼저 부순다) · 일반 건물 80(굳이 돌아가지 않는다).

주의: 시드 칸은 `integration[cell] = seedCost`로 덮이므로 **그 칸의 진입 비용은 계산에
들어가지 않는다** — 코어 HP가 아무리 커도 목표로서는 무해하다.

### 강 감속 — 효과 시스템을 쓰지 않는다

`MovementComponent.EffectiveSpeed = moveSpeed × SpeedMultiplier × TerrainMultiplier`.
효과는 시간 기반(지속·중첩·만료)이고 지형은 위치 기반이라 칸을 벗어나면 즉시 원복돼야 한다.
별도 계수라 감속탄과 강이 겹치면 자연스럽게 함께 곱해진다(0.5 × 0.5 = 0.25).

### 건설 판정

`PlacementSystem`이 프리뷰와 실제 배치 양쪽에서 `CanBuildFootprint`를 검사한다
(실패 사유: "지을 수 없는 지형 (강·절벽 또는 맵 밖)").

### 검증 (플레이 실측)

```
건물 칸(코어)  진격=210(10+상한200) · 보행=∞ · IsWalkable(ignoreBuildings)=True
빈 지면        진격=10 · 보행=10
강             진격=30 · 보행=30 · 속도배율 0.5
절벽           진격=∞ · 보행=∞
플로우필드     강 앞에서 (0.71, 0, 0.71) — 정면 통과가 아니라 대각 우회
코어 자동설치  맵의 core(59,59) → 월드 (60.5, _, 60.5)
```

### 남은 것

- **재계산 비용**: 건물 배치/파괴마다 전체 다익스트라(121² = 14,641칸). `dirty` 플래그로
  프레임당 1회로 합쳐지지만, 400×400(160,000칸)까지 커지면 증분 갱신이 필요하다.
- **경로 없음 폴백**: `GetDirection`이 zero면 `FlowFieldState`가 그대로 멈춘다. 지금은 건물이
  전부 목표라 잘 안 생기지만, 절벽으로 갇힌 스폰은 맵 에디터의 BFS 검증이 잡아야 한다.
- 광맥·둥지 자동 배치(`nodes`·`nests`)는 아직 SO에만 들어오고 씬 인스턴스를 만들지 않는다.

### 지형 시각화 — 타일을 지우고 깎는다 (`WorldTerrainGenerator`)

`Tools > Factory > Build World Terrain` — **에디터 타임 생성**이다. 런타임이 아닌 이유는
라이트 베이킹·수동 장식·검수가 가능해야 하고, 맵이 바뀔 때만 다시 구우면 되기 때문이다.

처음엔 칸마다 박스를 굽는 메시 방식을 썼다가 버렸다. **지형은 격자에 맞을 이유가 없다** —
길찾기는 이미 맵 데이터가 담당하므로, 보이는 지형은 그 위에 자유롭게 얹으면 된다.
그래서 Unity Terrain(heightmap)으로 갈아탔다.

**타일을 자연스러운 지형으로 바꾸는 세 단계**:

1. **거리장** — 절벽/강 각각에 대해 "가장 가까운 그 타일까지 몇 칸인가"를 체임퍼 2-pass로
   구한다(직교 1, 대각 1.414). 칸 안팎의 0/1 대신 연속값이 나오므로 경계가 매끄러워진다.
2. **도메인 워핑** — 거리장을 조회하는 **좌표 자체**를 펄린 노이즈로 흔든다(세기 2.4칸).
   경계선이 직선·직각을 잃고 구불거린다. 강이 굽이치는 것도, 절벽 능선이 들쭉날쭉한 것도
   전부 이 한 줄에서 나온다.
3. **잦아드는 거리 = 경사** — 높이/거리가 곧 기울기다. 절벽은 falloff 1.0(약 74°, 걸어
   오를 수 없는 벼랑), 강둑은 1.2. 여기에 미세 노이즈(±0.14m)를 더해 지면이 평평판을
   면하게 한다.

| 조각 | 높이 | 비고 |
|---|---|---|
| 지면 | 0 ± 0.14 | 기준면 |
| 강바닥 | −0.85 | 물 표면(−0.15)보다 넉넉히 깊어야 한다(아래 "다듬기" 참고) |
| 절벽 | +3.6 | 사람 키를 넘겨 시야를 끊는다 |

### 계단 지우기 — 두 번 다듬는다

타일이 네모라 거리장 등고선이 90°·45°로 꺾인다. 그대로 두면 마인크래프트처럼 각진다.
**한 곳에서만 다듬으면 소용이 없다**:

1. **거리장 다듬기** — 칸의 4배 격자(`FieldSubDiv`)에서 뜨고 반경 0.5칸 블러를 2겹.
   칸 단위로 뜨면 계단 하나가 곧 한 칸이라 어떤 보간으로도 각이 남는다.
2. **높이맵 다듬기** — 거리장을 아무리 뭉개도 "타일 밖은 0" 클램프가 **칸 격자에서**
   일어나기 때문에 경계선이 다시 칸 모서리를 따라간다. 격자를 떠난 뒤 한 번 더 펴야
   그 직각이 실제로 없어진다. 미세 굴곡은 이 블러 **뒤에** 얹는다(먼저 넣으면 지워진다).

**깎이는 쪽은 언제나 자기 타일이다.** 블러는 형상을 옆 지면으로 흘려보내는데, 그러면 절벽이
깎이는 게 아니라 **옆 땅이 차오르는** 모양이 된다 — 그 자리가 건물을 놓는 땅이라 더 곤란하다.
두 장치로 막는다:

- **`ShapeInset` 0.15칸** — 형상의 발치를 타일 경계보다 안쪽에 둔다. 경계에 딱 맞춰 세우면
  다듬는 과정에서 반드시 넘친다. 덤으로 경계선이 칸 격자를 벗어나 거리장의 매끈한 등고선
  위에 놓인다(그래서 거리장에서 "타일 밖은 0"으로 자르던 코드를 지웠다 — 그 자르기야말로
  경계선을 칸 모서리에 도로 붙여놓던 범인이다).
- **타일 밖에서는 블러를 무효화** — 거리장으로 판정한다. 칸 중심/경계로 재면 그 되돌림이
  칸 주기로 반복돼 물가에 가리비 같은 물결이 새로 생긴다(격자를 지우려다 다시 그리는 꼴).
  발치가 이미 안쪽이라 여기서 잘라도 잃을 높이가 없다.

경사(`CliffFalloff` 0.12 / `RiverFalloff` 0.08)는 짧게 세운다. 절벽·강 타일은 어차피 건설
불가라 칸 안에서는 마음껏 깎아도 되고, 경계선은 이미 매끈하므로 짧게 세울수록 또렷한
벼랑·물길이 된다. 반대로 경사를 칸 하나에 걸쳐 눕히면 폭 1~2칸짜리 형상이 제 높이에 닿기도
전에 반대쪽 경계를 만나 밋밋한 둔덕이 된다(0.6칸일 때 절벽 43%가 절반 높이도 못 됐다).

강을 0.55m가 아니라 **0.85m**로 파는 이유도 같다 — 다듬기가 폭 1칸 물길의 바닥을 들어올려서,
여유가 없으면 그런 구간에서 물이 끊겨 보인다(0.55m일 때 강 칸의 35%가 물 밖이었다).

물은 **맵 전체를 덮는 사각 통메시 한 장**(y=−0.15, 콜라이더 없음)이다. 강 모양을 따라 만들
필요가 없다 — 지형이 강 자리만 파여 있으니 거기서만 물이 드러나고, 물가는 지형이 올라오며
저절로 얕아진다.

**절벽은 물리 레이어가 아니라 맵 데이터로 막는다.** Terrain은 콜라이더가 하나라 부분적으로
레이어를 줄 수 없다. 대신 `GridManager`가 `TileRules`로 절벽을 통행 불가로 굽고, 플레이어는
74° 경사가 `CharacterController.slopeLimit`에 걸려 못 오른다. 지형 콜라이더는 Ground
레이어라 그리드의 장애물 검사(Obstacle)에 끼어들지 않는다.

URP 함정 셋 — 전부 "조용히 아무 일도 안 일어나는" 종류다:
- **`terrain.materialTemplate`을 비워두면 지형이 아예 안 그려진다**(물만 보인다).
  `Universal Render Pipeline/Terrain/Lit`을 명시해야 한다.
- **`AssetDatabase.CreateAsset`이 알파맵을 초기화한다** — 스플랫은 반드시 에셋으로 굳히고
  Terrain 오브젝트까지 만든 **뒤에** 칠해야 한다. 순서를 바꿔도 에러가 없고, 지형이 통째로
  첫 레이어(풀) 색으로 나올 뿐이라 원인을 짚기 어렵다.
- **URP Lit의 색은 `_BaseColor`다** — `Material.color`(_Color)만 넣으면 흰색으로 남는다.

검증(전 칸 `Terrain.SampleHeight`): **건설 가능 칸 13,737개 전부 높이 이탈 0** ·
**절벽에 인접한 지면 396칸의 최대 높이 0.11m**(미세 굴곡 범위 — 땅이 차오르지 않았다는 증거) /
강 362칸 중 295칸 수몰(나머지는 물길 끝단) / 물 콜라이더 없음 / 지형 콜라이더 레이어=Ground /
높이맵 513 · 알파맵 1024.

## 2026-08-16 — 둥지·광맥을 맵이 세운다 (TestNest 머지 후)

main의 TestNest(PR #62)가 둥지·밤 웨이브를 들고 왔다. 그쪽은 **씬에 손으로 배선**하는
전제였고 우리는 같은 정보를 맵 데이터로 갖고 있었다. 맵이 소유하는 쪽으로 합쳤다 —
씬에 박아두면 맵을 갈아끼울 때 배치가 따라오지 않아 "새 맵인데 옛 둥지가 서 있는" 상태가 된다.

### 늘어난 맵 스키마

```jsonc
"nests": [{
  "x": 40, "y": 80,
  "warningRange": 25, "triggerRange": 15,
  "defenseSpawnAmount": 3, "defenseSpawnCooldown": 10,
  "spawnPoints": [{ "x": 1, "y": 0, "hasBoss": true }],

  // 교전 규칙 — 안쪽부터 min ≤ max ≤ chase ≤ leash. 생략(0)하면 교전 구역을 두지 않는다
  "engageMinRange": 7, "engageMaxRange": 15,
  "chaseRange": 25, "leashRange": 30,
  "engageDayOnly": true,

  "bossRecoveryDays": 2, "nestRecoveryDays": 3
}],

// 밤 웨이브 진입로 — 둥지의 스폰 지점과 <b>별개</b>다
"nightSpawnPoints": [{ "x": 0, "y": 60 }]
```

**밤 진입로를 둥지와 나눈 이유**: 둥지의 스폰 지점은 낮에 플레이어가 다가왔을 때 방어
몬스터가 튀어나오는 자리이고, 밤 진입로는 코어를 향해 밀려드는 대문이다. 하나로 합치면
낮의 보스 자리가 밤의 대문이 된다(main의 `NightSpawnPointProvider` 주석이 같은 지적을 한다).

### 세우는 쪽 — `WorldPopulator`

`GameBootstrap.AssembleCombat`이 부른다. 맵의 nodes·nests·nightSpawnPoints를 읽어
프리팹을 세우고, 밤 진입로 제공자를 `BattleManager`에 주입한다. 생성물은 월드 아래
`Spawned` 노드에 모은다 — 지형과 같은 원칙으로 다시 만들 때 통째로 지운다.

프리팹은 `World`가 들고 있다(맵이 "무엇을" 정하고 월드가 "어떤 껍데기로"). 수치는 전부
맵이 정하므로 프리팹은 껍데기다.

**컴포넌트에 `Configure`를 낸 이유**: `ResourceNode`·`MonsterNest`의 수치가 전부
`private [SerializeField]`라 밖에서 넣을 수 없었다. 인스펙터 전용으로 설계된 것들인데
이제 맵이 정하므로 통로가 필요하다. 0 이하는 "프리팹 값을 그대로 둔다"는 뜻이라,
맵이 일부만 지정해도 나머지는 프리팹 기본값이 산다.

### 인스턴스 소유는 부트스트랩으로 통일

main이 들고 온 `preferSceneInstance`(씬 인스턴스가 부트스트랩 것을 런타임에 밀어냄)를
제거했다. `GameBootstrap`이 탐색을 독점하고 씬에는 미리 두지 않는 방식과 정반대라,
두 방식이 공존하면 "누가 인스턴스를 소유하는가"의 답이 씬마다 달라진다.
